# Параллельное интегрирование по энергии

Настройка в Keldysh/main.cpp:
    settings.numerical.energy_threads = 0;

0 — автоматически max(1, hardware_concurrency()-1).
На данном ПК определяются 16 логических процессоров: используются 15 рабочих потоков.
1 — однопоточный расчёт; >1 — явно заданное число рабочих потоков.
Число рабочих потоков ограничено Neps. Если аппаратное число неизвестно, используется один.
Это число одновременно работающих вычислительных потоков, без закрепления конкретного ядра.
ОС сама распределяет их по логическим процессорам.

В NumericalParams по умолчанию energy_threads=1 для совместимости.
В main.cpp включён автоматический режим. Пользовательские NF=4, Nx=25, Neps=1024,
mixing=.8, depth=6, L_N=1 и допуски сохранены.
Текущий mode="iv" также сохранён.

Распараллелена solve_current_for_voltage в Keldysh/sns/current.cpp.
Для каждого напряжения сетка по энергии разбивается на непрерывные участки.
Рабочий поток решает gamma/tilde и распределение, затем вычисляет спектральные токи
для энергий своего участка. У каждого потока собственные матрицы и история Anderson.

При наличии решений предыдущего напряжения используется initial[j].
Иначе первая энергия каждого участка стартует без initial, а последующие используют
предыдущую энергию внутри своего участка. Поэтому результат без готового initial может
слегка отличаться от однопоточного в пределах допуска нелинейного solver.
При одном потоке прежняя последовательность начальных приближений сохраняется.

Потоки записывают результаты в разные элементы массивов по исходному индексу энергии.
После join максимум невязок и интеграл тока вычисляются последовательно в порядке энергий.
Численная квадратура, нормировка и формулы тока не изменены.
Выходной массив solutions публикуется только после успешного завершения всего расчёта.

Исключения перехватываются внутри рабочих потоков, прекращают выдачу следующих энергий
и передаются вызывающему коду после join. Частичный ток не возвращается.
При ошибке создания потока уже запущенные потоки также корректно завершаются.

В обычном режиме спектральные и кинетические задачи выполняются параллельно.
Если включён G/F iteration_log_path или anderson_verbose, спектральная часть защищена
общим mutex, чтобы существующий журнал не перемешивался; кинетическая часть остаётся
параллельной. Для максимальной скорости оставьте эти подробные журналы выключенными.
Существующий вывод FINAL сохранён; каждая строка защищена короткой блокировкой.
Порядок строк FINAL при параллельной работе может отличаться от порядка энергий.

Память кинетического solver нужна каждому рабочему потоку отдельно.
В консоли выводится приблизительная суммарная оценка его рабочих массивов в MiB.
Это не оценка всей памяти процесса. Существующий max_block_bytes остаётся лимитом
одной кинетической задачи; автоматического ограничения суммарной RAM не добавлено.
Если памяти недостаточно, уменьшите energy_threads. Физические сетки автоматически не меняются.
